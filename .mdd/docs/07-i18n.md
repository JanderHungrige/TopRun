# 07 — Languages (English / German)

## Purpose

The whole game is playable in English or German. A **language button in the start menu**
switches between them instantly; the choice is saved with the progress. Default: English.

## Architecture

```
i18n/i18n.ts        Lang, getLang/setLang, t(key, params), line(key, params, seed), interpolate()
i18n/ui-en.ts       UI strings (source of truth for the key set: UiKey = keyof typeof UI_EN)
i18n/ui-de.ts       Record<UiKey, string> — the compiler rejects a missing German key
i18n/content.ts     language-aware accessors over src/data tables:
                    missionName/Briefing, theaterName/Tagline, planeDescription/SpecialName,
                    secondaryDescription, equipmentName/Description/LevelText, enemyName(kind, n),
                    bossTitle, objectiveText(objective)
i18n/content-de.ts  German names/descriptions for planes, weapons, equipment, enemies, bosses, theaters
i18n/missions-de.ts German mission names and briefings (all 30)
i18n/lines-*.ts     character lines (doc 06)
```

English content stays in the `src/data` tables (single source); German lives in the i18n
tables keyed by the same ids.

## Data Model

`settings.lang: 'en' | 'de'` in the save (01); unknown values parse to `'en'`.

## API Endpoints

None.

## Business Rules

- `t(key, params)` returns the string for the current language with `{name}` placeholders
  replaced; a missing param leaves the placeholder visible (bug is obvious, never a crash).
- German must cover **every** key — enforced at compile time for UI keys and line keys, and by
  unit tests for content tables (all 30 missions, all enemy kinds, planes, weapons, equipment,
  theaters, bosses).
- English and German strings for the same key use the **same placeholder set**.
- Not translated (proper names): aircraft and weapon designations (F-14, AIM-9 …), boss names
  (IRONCLAD …), callsigns, the TopRun logo and its "CARRIER STRIKE" tagline.
- Plurals: enemy names carry explicit singular and plural forms per language
  (`enemyName(kind, count)`).
- Switching language takes effect on the next rendered frame everywhere (scenes read strings at
  render time; nothing caches translated text except the static map layer, which is rebuilt on a
  language change).
- Start menu button label shows the *current* language in that language:
  "LANGUAGE: ENGLISH" / "SPRACHE: DEUTSCH".
- Number formatting stays `$12,345` in both languages (arcade money, not real currency).

## Data Flow

`save.settings.lang` → `setLang()` at boot and on the menu button → `t()/line()/content` read
`getLang()` at render time.
