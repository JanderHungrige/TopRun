# 33 — Image Portraits

## Purpose

Owner decision (2026-10-26): the characters' faces are no longer drawn in code. The owner generates pixel-art
portraits with their own ComfyUI workflows — **"Top Gun pixel pilot portrait"** and **"Top Gun pixel crew
portrait"** (FLUX.2 klein, rendered at 720 × 864, reduced by area to **240 × 288**, **64 colours**, saved as
indexed PNGs on a true pixel grid) — and the game shows those images: the three pilots on pilot select, the
admiral, the deck officer (shooter), the crew chief and the wingman. "Create your own" picks from a
matching set of generated portraits. They are generated illustrations, never photos of people. The procedural
portraits and avatars (docs 20 / 29, art v1 and v2) are retired.

## Assets (`src/assets/portraits/`, owned and generated by the owner)

| File | Use |
|------|-----|
| `pilot1.png`, `pilot2.png`, `pilot3.png` | the three preset pilots |
| `admiral.png` (+ `-talk`, `-half`) | the admiral — no blink frame (dark sunglasses) |
| `shooter.png` (+ `-talk`, `-half`, `-blink`) | the catapult / deck officer |
| `chief.png` (+ `-talk`, `-half`, `-blink`) | the crew chief |
| `wingman.png` (+ `-talk`, `-half`, `-blink`) | the wingman, Lt. "Duke" Carter in the cockpit |
| `custom/<age>-<skin>-<hair>-<length>.png` | the builder set: age `kid|adult`, skin `fair|olive|brown|dark`, hair `black|brown|blond|red`, length `short|long` (64) |

Talk, half and blink frames are identical to the base outside the mouth / eyes (`-talk` = mouth open,
`-half` = lips slightly parted). Every file is discovered with
`import.meta.glob(…, { eager: true, query: '?url', import: 'default' })` (`assets.ts`), so whatever exists is
bundled as a hashed asset and anything missing is simply absent — the code works with any subset.

## Rendering (`src/render/portraits/image.ts`)

- `HTMLImageElement`s are created and cached per URL; `preloadPortraits()` (called at boot) loads the six fixed
  characters (and their talk / blink frames). Custom picks load on first use; the builder preloads the set.
- `drawImagePortrait(ctx, frames, box, state)` places the image like `drawBust` placed portraits: **cover-fit,
  bottom-aligned, centred, clipped** to the box, `imageSmoothingEnabled = false`, the target rectangle snapped to
  whole device pixels — a box of exactly the image's size (the NEW PILOT cards, 240 × 288) shows it 1 : 1 in
  device pixels at DPR 1, 2 : 1 at DPR 2. When the bob lowers the image, the gap above it repeats the image's top
  (sky) row. While an image loads the box shows a dark placeholder; a custom pick with no image at all shows a
  dark pilot silhouette.
- Boxes smaller than the image (fewer device pixels than image pixels — the PILOTS list, speech boxes, the
  map header, the radio strip) get a **reduced copy**: an area average back onto the image's own colours
  (`pixel/reduce.ts`, pure, cached per size) drawn 1:1 — never a blurred, smoothed draw.
- Animation (`src/game/portrait-frames.ts`, pure): a 1-image-pixel breathing bob; a blink (if the character has a
  blink frame) once every 3–6 s for 120 ms with a per-character phase; the mouth frames follow the speech box's
  `mouth` value (doc 06: closed 0 / half 0.5 / open 1, each held ≥ 0.15 s): open → `-talk`, half → `-half`
  (if the character has one; without it half shows the closed base), closed → the base.
- Overlays on the composed image: the gold `selected` frame (pickers) and the green **radio feed** (the image
  remapped onto the phosphor ramp by luminance, plus scanlines, flicker and brackets) — `overlays.ts`.
- **Moods and gestures are ignored** for image portraits: one expression per character.

## Who uses what

- `drawPortrait(ctx, id, box, state)` (doc 06, unchanged API): admiral, shooter, chief and wingman → their
  images. The wingman is Lt. "Duke" Carter in the cockpit: his face from 'Top Gun pixel crew portrait', then that
  image through 'Top Gun pixel pilot – cockpit' (helmet, hanging oxygen mask, harness). The procedural portrait
  code (`procedural.ts`, `wingman.ts`, `features.ts`, `hands.ts`, `pixel-cast.test.ts`) is deleted; `parts.ts`
  stays (the jets and enemies use it).
- `drawPilotAvatar(ctx, face, box, state)` (doc 29, unchanged API): `pilot1–3` → `pilot1–3.png`; a custom pick →
  exactly its own `custom/…png` (`portraitKey`; a silhouette while that file is missing — owner testing showed a
  nearest-match fallback with a half-generated set makes every pick look the same). Used by
  NEW PILOT, the pilot list, the map header and the builder.

## Builder v3 (`src/game/avatar-look.ts`, `src/scenes/avatar-builder*.ts`)

```ts
interface AvatarLook { age: 'kid' | 'adult'; skin: 'fair' | 'olive' | 'brown' | 'dark'; hair: 'black' | 'brown' | 'blond' | 'red'; length: 'short' | 'long' }
```

- Four rows ◀ ▶ (AGE, SKIN, HAIR COLOUR, HAIR LENGTH; EN + DE labels), RANDOM, CANCEL, DONE, and ORIGINAL for an
  existing pilot. The preview is the matching custom portrait (a silhouette until it is generated).
- `parseLook` migrates the old v1/v2 looks (`{ hair: style, hairColor, skin, … }`): skin index of the 8 old tones
  → 4 buckets (pale·light → fair, ruddy·tan → olive, olive·brown → brown, deep·ebony → dark), hair colour family
  (black · dark brown, brown, chestnut → brown · auburn, strawberry, ginger, pink → red · golden, blond, platinum,
  silver → blond · blue → black), long / ponytail / braids / bob → long, anything else short, age → kid.
- `lookKey(look)` = `<age>-<skin>-<hair>-<length>` = the asset name; `randomLook(seed)` deterministic.
- Accent colour of a custom pick: by hair colour. `playerPerson(face)` (full-body scenes: push-ups, volleyball,
  motorbike, piano, ceremony, hangar walker) derives skin, hair colour and the kit hair style (kid short → messy,
  adult short → crew, long → long) from the pick, with olive suit trousers; presets keep their own looks.

## Business Rules

- The game never generates, edits or ships photos; all portraits are the owner's generated illustrations.
- Image portraits are always drawn nearest-neighbour or from a reduced copy, never smoothed.
- A missing image never breaks a screen: placeholder while loading, silhouette for a custom pick not generated yet.
- Old saves keep working: a stored v1/v2 look becomes the nearest pick on load.

## Verification (2026-10-26)

save parsing), `tsc --noEmit`, production build (PNGs emitted as hashed assets, smaller JS); browser: NEW PILOT,
